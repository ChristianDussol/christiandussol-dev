# Episode 3: goose

### **The runtime that brings them together**

A protocol says how an agent reaches your systems. A convention says how a repository explains itself. Neither of them runs anything.

goose is the third piece: **the local process that holds a model, its tools and a task together for the length of a session.** Started inside Block, built in Rust, and donated in December 2025 to the Agentic AI Foundation, where it sits alongside MCP and AGENTS.md as one of the three founding projects.

📎 **See it**: [AAIF Project Focus: goose carousel (PDF)](https://github.com/christian-dussol-ai-native/goose/blob/main/carousel/AAIF%20Project%20Focus%20-%20goose.pdf), an 11-slide introduction that assumes no prior exposure to agentic coding tools

### What the carousel covers

* **What an agent runtime is**, and how it differs from a protocol or a convention. The distinction is easy to state and easy to lose: MCP is connectivity, AGENTS.md is context, and a runtime is where both are put to work
* **How goose fits together on your machine.** Local-first and model-agnostic, an MCP client you can point at any provider
* **What it packages that a prompt cannot.** Workflows as versioned files rather than instructions passed around a channel

→ **Browse it**: [goose](https://github.com/christian-dussol-ai-native/goose) on GitHub, a resource repository with nothing to install and nothing to run

### Where it sits in the series

MCP is connectivity. AGENTS.md is context. **goose is where both are put to work.** The three were donated together, and reading them in order is the shortest path to seeing why.
